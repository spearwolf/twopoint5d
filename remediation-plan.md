## Entscheidungen
- `IProjection.getViewRect()` liefert ein Objekt `{width, height, pixelRatioX, pixelRatioY}` statt des Tuples; harter Break, alle eigenen Aufrufer (Library, Lookbook, Browser-Tests, Doku-Codeblöcke) ziehen mit, Eintrag im Migration Guide (2026-09-29)
- `getZoom()` wird aufgeteilt: das Interface bekommt eine Methode mit einer für beide Projektionen festgeschriebenen Semantik, die andere Bedeutung wandert unter einen eigenen Namen. Die Namen wählt Zug 0 von Paket 2 und legt sie dem Nutzer dort vor; Migration Guide (2026-09-29)
- Namen und Bedeutungen der `getZoom()`-Aufteilung, vom Nutzer gewählt in Zug 0 von Paket 2: `IProjection#getScaleFactor(distanceToCamera)` — wie viel größer etwas in dieser Entfernung erscheint als auf der Projektionsebene, orthografisch `1`, parallaktisch `D/d` (`D` = Abstand der Kamera zur Projektionsebene); der bisherige parallaktische Wert `1 − d/D` wandert nach `ParallaxProjection#getParallaxFactor(distanceToCamera)` und nicht ins Interface; `getZoom()` entfällt auf dem Interface und in beiden Implementierungen, Migration Guide (2026-09-29)
- Helper-Builder für gängige Effekt-Stacks (fertige `buildOutputNode`-Callbacks) und ein RenderTarget-Pool für gleich dimensionierte Renderer werden umgesetzt, nicht als acknowledged gebucht (2026-09-29)
- Clear-Policy wird dokumentiert, nicht umgebaut: `clear` ist das einzige Clear, `renderer.autoClear` ist während der Stage-Draws immer aus — README und TSDoc sagen das an beiden Stellen (2026-09-29)
- Das interne RenderTarget von Modus C wird immer vollständig zu transparentem Schwarz (0, 0, 0, 0) geleert; die Clear-Farbe des Renderers wird danach eigens aufgetragen, wie beim verschachtelten Kind (2026-09-29)

- `Canvas2DStage.texture` wird ein reiner Getter; Migration Guide (2026-09-29)
